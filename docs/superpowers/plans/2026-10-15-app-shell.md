# App Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the single-row text navbar with a Facebook-style shell: sticky icon top bar with search, badges and an account menu; a left sidebar of shortcuts; a centred content column with a Facebook-style post composer.

**Architecture:** The `(app)` layout renders `TopBar` (server, with client `NavTabs` and `AccountMenu`), `Sidebar` (client, for the active row) and the `main` column. Active-route logic is a pure function in `src/lib/nav.ts`. Icons are inline SVG components in `src/components/icons.tsx`. The composer keeps its form contract.

**Tech Stack:** Next.js 16 App Router, Tailwind 4, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-15-app-shell-design.md`

## Global Constraints

- One `navigation` landmark only (the top bar). It must contain the user's name, and `Friends (n)`, `Messages (n)`, `Notifications (n)` as text when n > 0, and must not contain `Messages (` when n is 0.
- Keep the composer label text "What's on your mind?" (sr-only) and the `Post` button name.
- `Log out` stays a `<button>` inside a `<form action={logOut}>`.
- No new dependencies. Light theme only.
- Commit messages end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`. Do not commit `prisma/schema.sql`.

## Review Focus

1. Badge labels: e2e messages/notifications/friends specs depend on exact `Label (n)` text in the nav.
2. Account menu must be keyboard operable (button, `aria-expanded`, Escape closes) and the Log out form must still post.
3. Layout at 390 px: no horizontal scroll, top bar fits, sidebar hidden.
4. `isActive` must not mark `/pages` active on `/p/<id>` (post pages) or `/people`.
